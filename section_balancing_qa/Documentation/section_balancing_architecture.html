1Executive Summary

Splitting a large enrolled class into multiple sections under a fixed room capacity is an instance of Multiway Number Partitioning (also known as Balanced Bin Packing): given N students and a maximum capacity C per room, divide N into the fewest possible groups such that no group exceeds C, while keeping the groups as close in size as possible. Done naively — filling sections first-come-first-served until each hits capacity — this produces lopsided distributions: a course of 14 students against a 13-seat room would naively yield a 13/1 split rather than the sensible 7/7.

This engine eliminates that failure mode by dynamically computing the target section count and target load before assigning a single student, rather than greedily filling sections and dealing with the leftover. Student assignment becomes the final step of an already-solved partitioning problem, not a source of imbalance.

Result Across four deliberately distinct test cases — an evenly-divisible split, a large cohort with a remainder, an odd-number squeeze, and a single-section fit — an independent diagnostic validator confirmed all four produced the mathematically optimal partition, with zero capacity violations, zero misplaced/duplicated students, and zero avoidable load imbalance.

2Mathematical Strategy & Algorithmic Design

2.1 Required section count

For a course with N students and room capacity C, the minimum section count is a hard floor:

k = ceil(N / C)

Any fewer sections and at least one would mathematically have to exceed C, regardless of arrangement.

2.2 Dynamic target load

Given k, the ideal average load per section is:

L = ceil(N / k)

This represents the size of the largest section in a perfectly balanced split — every other section will be L or L−1.

2.3 O(1) multiway partitioning via divmod

Rather than searching for a balanced split, the engine computes it directly in constant time:

base, remainder = divmod(N, k)
sizes = [base + 1] * remainder + [base] * (k - remainder)

This is provably the minimum-spread partition of N into k integer parts — no other split has a smaller gap between largest and smallest group.

3Achievable-Optimum Validation Philosophy

3.1 The formula, taken literally, rejects correct answers

The specified soft-balance metric is Penalty = Σ(ActualSize_i − L_target)². Taken literally, this is non-zero even for the best possible split whenever N doesn't divide evenly by k. Take CS101 (N=82, k=3): the optimal partition is [28, 27, 27], scored against the scalar L_target=28:

(28-28)² + (27-28)² + (27-28)² = 0 + 1 + 1 = 2

A validator flagging any non-zero result as failure would reject this schedule — even though no better partition exists. Roughly half of all (N,k) pairs have a remainder, so a literal penalty > 0 threshold produces false positives on a huge fraction of legitimately optimal schedules.

3.2 The fix: compare against the achievable minimum, not zero

The validator computes the formula exactly as specified, but also computes the penalty of the divmod-optimal partition for that same (N,k) — the best any solver could possibly achieve. A course only fails if:

FAIL only if:  Penalty_actual  >  Penalty_min_achievable

This turns the metric from "is this perfectly uniform" (impossible with a remainder) into "is this as good as it could possibly be" — the only meaningful question. Both numbers are always printed; nothing is hidden behind the verdict.

3.3 Proof this still catches real imbalance

Self-test: ITS101 (N=14, k=2, achievable minimum=0 with [7,7]) deliberately rebalanced into a lopsided [13,1] split:

Penalty_actual = (13-7)² + (1-7)² = 36 + 36 = 72
Penalty_min_achievable = 0
72 > 0  ->  FAIL
Confirmed The validator correctly rejected this deliberately broken input, proving the achievable-minimum comparison does not simply rubber-stamp every input — it still catches real, fixable imbalance while passing the legitimately optimal remainder-based splits.

4Diagnostic & Self-Healing Engine

Every validation run produces, per course, either an [OK] line or a structured failure with two parts: a Problem Statement and a Recommended System Solution.

4.2 Soft-rule diagnostics (the self-healing recommendation)

When actual penalty exceeds the achievable minimum, the engine reports the exact imbalance and a concrete transfer plan via greedy largest-excess-to-largest-deficit matching:

[FAIL] Course ITS101: Section ITS101-SEC1 has 13 students, Section
       ITS101-SEC2 has 1 student(s). Load imbalance delta = 12.
  (variance penalty = 72, best achievable for N=14/k=2 is 0 with sizes [7, 7])
[RECOMMENDED FIX] Move 6 student(s) from ITS101-SEC1 to ITS101-SEC2
                  to approach the target distribution [7, 7].

This is live output from the Section 3.3 self-test — including the precisely-computed transfer count (6 students) needed to restore the 7/7 balance, not a generic "rebalance needed" message.
